B · 主平台深色页的打印兜底层

报告是后端生成的独立浅色 HTML，但主平台的页面本身仍是深色——主机清单、告警列表、资产台账这类页面，值班同学会直接 Ctrl+P 交给别人。 这里给一份通用的打印兜底：只在 @media print 里覆盖令牌与容器，不动任何组件的正常样式，成本约半天。

两种失败形态：开启「打印背景图形」→ 满版黑底、极费墨、复印件全糊； 关闭（浏览器默认）→ 卡片背景消失但文字仍是浅色，白纸浅字几乎不可读。两条路都是废纸。

打印态规则

元素打印态处理理由
侧栏 / 顶栏 / 面包屑display:none纸面上无交互意义，占 1/3 版面
工具栏按钮、分页、筛选display:none打印件不需要"点击"，且会被误认为可操作
卡片容器（.glass/.kpi/.panel/.ov-card）白底 + 1px solid #d8dee9硬编码白色半透明边框在白底上不可见
语义色（严重/警告/正常）保留 + print-color-adjust:exact去掉颜色后无法分辨严重程度
ECharts 画布保持彩色，禁止 break-insideCanvas 能正常打印，但会被分页切断
长表格thead{display:table-header-group}跨页后表头要重复
链接显示 href 于文字后（仅外链）纸质件上 URL 才有意义

顺带补一个入口

只加打印 CSS 仍然依赖用户自己 Ctrl+P 并记得勾选项。建议在页头操作区加一个「打印/存为 PDF」按钮， 点击后 window.print()，并在 URL 上带 ?print=1 让页面临时切到打印预览态（隐藏交互控件、内容区撑满宽度）， 所见即所得，避免"打出来跟屏幕上不一样"的反复试错。

C · 对外状态页 /status 浅色版

StatusView.vue 的样式其实已经写成浅色友好（var(--border-color,#e5e7eb) 带浅色兜底值）， 但 main.js 在启动时全局 classList.add('dark')，所以这个对外页现在也是深色。 这是全站唯一一处"给外部人看"的页面，浅色是对的——外部访客、甲方、领导截图转发，深色截图在微信/邮件里观感差、打印即废。

语义色必须换值：深色下用的 #67c23a（绿）在白底上对比度仅 2.6:1，不满足 WCAG AA（需 4.5:1）。 浅色下要整体加深：绿 #15803d、红 #b91c1c、橙 #b45309。这是浅色模式最容易漏的一点。

① 报告模板打印修正（约 2 小时）

文件：internal/server/report/template.html —— 改 hero 配色、补分页与页眉页脚。

/* 1) hero 不依赖背景图形：白底 + 品牌色左条 */
.hero{ background:#fff; color:#111827; border:1px solid #d8dee9;
       border-left:4px solid #1d4ed8; border-radius:8px;
       box-shadow:none; padding:18px 22px; }

/* 2) 分页控制 */
@media print{
  @page{ size:A4; margin:16mm 14mm; }
  thead{ display:table-header-group; }   /* 跨页重复表头 */
  tfoot{ display:table-footer-group; }
  .section, .stat, .chart-card, .finding{ break-inside:avoid; }
  h2,h4{ break-after:avoid; }             /* 标题不与内容分离 */
  .chart-card svg, .badge, .finding{ -webkit-print-color-adjust:exact; print-color-adjust:exact; }
  body{ background:#fff; font-size:11.5pt; }  /* pt 更适合纸面 */
}
