# 配置项模型页（设计件）

> 范围：把资产台账的"**模型**"（有哪些配置项类型、每个类型有哪些配置项、哪些配置项会被巡检比对）
> 变成看得见、并且**其中两处可维护**的页面。
>
> **明确不做**：自定义类型的增删改（理由与影响面见 §2）。
>
> 状态：**待评审**（决策点 D1~D9 需要拍板）。实施记录将追加到本文末尾。

## 1. 背景：那一行欠账的真实形态

能力全景表 `2026-09-30-ops-platform-capability-map.md:110`：

```
| 资产台账：配置项模型页 / 关系视图页 | 部分实现 | 关系视图页已落地（2026-10-06）……
  **未做**：配置项模型页（自定义类型的字段 Schema 编辑，asset_types.schema 目前只存不解释）| P2 | L |
```

调研把这句话拆开看，实际是这样：

| 事实 | 位置 |
|---|---|
| `asset_types(key, title, builtin, schema)` —— **`schema` 列只存不解释**，`BuiltinTypes()` 从不给它赋值 | `asset/store.go:26-31`、`asset/model.go:104-106` |
| 属性是 `asset_attrs(asset_id, key, value, source, updated_at, updated_by)`：**采集与人工并存、人工优先**，值**全是字符串** | `asset/store.go:45-53`、`model.go:218-232` |
| 属性**没有任何元数据**：没有中文名、单位、取值类型、是否敏感、展示顺序 | 全仓 grep 无 |
| 类型键与属性键**都没有字符集/长度校验**（未知类型写入靠 `typeExists` 拒） | `api/asset_api.go:1102`、`asset/service.go:219` |
| 平台里**唯一**收敛的属性规则是巡检的**运行态排除清单**：`runtimeFields{up,status,uptime,uptimeSeconds}` + `focusFields()`，**快照 / 巡检 / 标杆共用同一实现** | `asset/service.go:755-757`、`:1176-1204` |
| 前端：类型选项**多处硬编码**（列表筛选 `:48`、新建表单 `:592-613`、类型显示名 `typeLabel()` `:952`、巡检页执行区 `:19`、**周期化巡检卡 `:63`**——最后这处是 1.30.44 刚加进去的，等于又添了一个同类型硬编码点） | `AssetListView.vue`、`InspectView.vue` |
| 设计件里只有一条**未实现**的接口草案 `GET /api/v1/asset-types # 类型与字段 schema` | `2026-09-30-asset-cmdb-design.md:120` |
| 两个页面在原型里标 D3，当时**有意未做**；「巡检误报 → 关注字段集合**显式声明**」这条决策也还没有载体 | 同上 `:284`、`:166` |

**结论**：这条欠账不是"少一个页面"，而是**模型没有载体**——属性只有键名，规则散在代码里，
界面上既看不到"这个类型有哪些配置项"，也看不到"哪些字段会被巡检比对"。

## 2. 明确不做：自定义类型的增删改

原型那句"自定义类型的字段 Schema 编辑"暗示可以**造类型**。本批不做，因为"加一个类型"在这个平台
不是加一行数据，而是多点改代码（调研逐个列出）：

- 类型常量 + `BuiltinTypes()` + 短命对象登记 `EphemeralTypes()`（`asset/model.go:75-121`）；
- 前端**四处硬编码**（列表筛选/新建表单/类型显示名/巡检页类型下拉）；
- 台账列表的类型筛选、健康度摘要（短命对象不计入）、拓扑节点显示名、新建表单的字段集，
  每处都要按新类型给出口径——尤其**健康度与资源范围**：新类型若没有归属节点，`nodeInScope`
  会把它的关系整条剔除（这条权衡在关系域已经吃过一次，见 `refactor-plan` 里"不要给中间件引集群类型"的结论）。

要做它，前置是"**类型注册表 + 逐类型的能力声明**"（哪些进列表、是否计入健康度、有无节点归属、
允许哪些关系），那是另一个量级的设计。本批把**模型可视化 + 两处可维护**做实，并在这里写明：
**将来要做自定义类型，先做那张能力声明表**。

## 3. 决策点

| # | 问题 | 建议 | 理由 |
|---|---|---|---|
| **D1** | 范围：只读视图，还是可编辑模型？ | **只读视图 + 两处可维护**：① 每个类型的**比对字段模型**（运行态排除 + 关注字段）；② 属性的**说明**（中文名/单位/备注）。**不做**自定义类型 | 只读能把"模型长什么样"说清；而"哪些字段参与比对"是**唯一已有单一实现**的规则（`focusFields`），把它从代码常量搬进配置才是真正收敛；属性的中文名解决"抽屉里显示 `cpuCores`"这个每天都在看的粗糙处 |
| **D2** | 比对字段模型放哪、语义是什么 | 存进 `asset_types.schema`（按类型 `{runtimeFields:[...], focusFields:[...]}`）；`focusFields()` 改为**先读它、读不到用内置默认**（= 现有 4 个运行态键 + 其余全部）→ **存量行为零变化** | 单一数据源、且默认值与今天逐字相同；改动只在"有人真的去调它"时生效。**去掉 `up` 之类的后果要在界面上写清**（探活抖动会开始进差异清单） |
| **D3** | 属性说明的生效范围 | **只在展示上生效**（详情抽屉的属性列表显示中文名，原键仍可见、可搜索/可筛选）；**不进**巡检比对、不进导出列、不改筛选语义 | 说明是给人看的；一旦让展示层字段参与比对或导出，就是在动语义（而语义改动要比对前后行为，成本不一样） |
| **D4** | 属性键的治理（同一含义多种写法，如 `cpu` vs `cpuCores`） | 模型页**只提示**"疑似同义键"（同类型内归一化后相同：去分隔符/大小写），**不自动合并、不自动改名** | 自动合并是数据破坏且不可逆；先把事实摆出来（覆盖度、来源分布）让人自己决定 |
| **D5** | 权限 | 读 `assets:read`；**改模型用 `assets:write`**（与「标杆 = 台账数据维护」同一取向，不新增权限点） | 标杆已经用 `assets:write`（`inspect_api.go` 的口径）；模型与标杆同属"台账数据维护"。改比对字段模型会影响巡检结论，但那是**配置**而非"跑一次巡检"，因此不用 `inspect:run` |
| **D6** | 短命对象（Pod/工作负载）要不要出现在模型页 | **要**，并沿用 `EphemeralTypes()` 的标记在页面上写明"默认不计入健康度" | 模型是全量的；把它们藏起来反而让人以为平台不认识它们。标记的**唯一定义处**仍是 `EphemeralTypes()`，页面上不另写一份 |
| **D7** | 接口 | `GET /api/v1/asset-types`（模型 + 统计）与 `PUT /api/v1/asset-types/{key}`（改 schema）——名字兑现设计件 `:120` 的草案 | 草案已经写了这个名字，别再造一个同义接口 |
| **D8** | 统计口径（资产数、属性覆盖度、来源分布） | **按当前身份的资源范围统计**（与台账一致）；模型本身（类型与字段定义）不受范围限制 | 覆盖度本质是"台账数据的画像"，受限用户不该从模型页推出范围外的资产量与属性分布 |
| **D9** | 要不要显示属性的**示例值** | **不显示值**，只显示键 + 覆盖度 + 来源分布 | 属性值里可能有连接串、口令、内网地址。模型页是"看模型"，不是"看数据"；要看值去台账详情（那里本来就有权限与范围约束） |
| **D10** | 值**规范化**与**容忍列表**（设计件 `:166` 一并提过："关注字段集合显式声明 + 规范化后比较 + 允许容忍列表"） | **本轮只做前一半**：加一条"值比较前统一去首尾空白与行尾换行"的规范化（纯减少误报、不改字段集）；**容忍列表不做**，但把 `schema` 留出 `tolerance` 字段的位置 | 现在同值但差一个换行/空格就会被报成"变更"，这是巡检最常见的假差异之一，改一行代码就能消掉；而"按字段配容忍度"改的是**比较语义**（不同字段的正确容忍方式不同：数值按相对误差、字符串按空白/大小写），属于下一步，且它天然长在同一套 `schema` 上（`asset-cmdb-design.md:36-37` 把"字段集合 / 来源 / 是否可人工维护"定义为模型的一部分） |

## 4. 设计

### 4.1 数据（不新增表）

- `asset_types.schema` 从"空壳"变成**真实载体**：`{"runtimeFields":[...], "focusFields":[...], "attrMeta":{key:{title,unit,note}}}`
  - 向后兼容：读不出来（空/坏 JSON）→ 用内置默认，**绝不因此让台账起不来**（与保留策略"配置坏不阻断启动"同一取向）。
  - `builtin` 列继续区分内置/非内置（本批不会有非内置类型）。
- **属性说明按类型存**（不是按资产存）：同一个 `cpuCores` 在主机与中间件实例上的含义可能不同，
  这也是它天然属于"模型"而不是"实例"的理由。

### 4.2 接口

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| `GET` | `/api/v1/asset-types` | `assets:read` | 每个类型：`key/title/builtin/ephemeral`、资产数、属性清单（键、覆盖数、来源分布：仅采集/仅人工/两者都有）、`runtimeFields`/`focusFields`（含默认来源标记）、该类型的标杆资产与比对字段数 |
| `PUT` | `/api/v1/asset-types/{key}` | `assets:write` | 只接受 `runtimeFields` / `focusFields` / `attrMeta`；其它字段忽略。**写前校验**：键必须是非空字符串、去重、`focusFields` 与 `runtimeFields` 不得同时包含同一个键（否则"显式关注"与"运行态排除"自相矛盾） |

统计与模型一次返回（页面上本来就是一体）；**属性值一律不出现在响应里**（D9）。

### 4.3 规则收敛（本批真正的价值）

`focusFields()` 今天读的是包级 `runtimeFields` 常量。改为：

```
按类型取配置 → 有就用它 → 没有就用内置默认（4 个运行态键 + 其余全部）
```

快照 / 巡检 / 标杆三条路径**已经共用这一个函数**，因此收敛点只有一处（`asset/service.go`），
不需要动三处。**存量行为零变化**由"默认值逐字等于今天的常量"保证，并用例钉住。

### 4.4 前端

新增页面 `web/src/components/asset/AssetModelView.vue`（菜单「资产与配置 → 配置项模型」）：

- **上半：类型卡片**——类型名、资产数、短命对象标记、标杆资产、比对字段数；
- **下半：选中类型的属性表**——字段键、**中文名（可编辑，来自 `attrMeta`）**、单位、来源分布
  （两个 pill：采集/人工）、覆盖度（n/N + 条形）、是否运行态（可勾选/取消，带后果提示）、
  是否在关注字段集里；「疑似同义键」单独一段（D4）；
- **属性值的展示**：不显示（D9），只显示覆盖度与来源；
- 页头一行说明：**模型是"类型"的，不是"实例"的**——改这里不会改任何一台机器的现有值。

顺带把**多处硬编码的类型选项**（含巡检页那两处）统一改成读 `GET /api/v1/asset-types`；
这既是模型页的副产品，也消掉"加类型要改多处前端"的一半成本。**注意**：类型显示名改为从接口取之后，
接口不可得时要退回按 `type_key` 显示（不能变成空白）。

## 6. 用例与验证计划

**单测**：schema 读写的向后兼容（空/坏 JSON → 内置默认，且**不报错**）；`focusFields` 的三种情形
（无配置 = 今天的行为逐字相同、有配置按配置、配置里同时含 focus 与 runtime → 保存被拒）；
统计的**范围口径**（受限身份只见范围内的资产数与属性分布）；`attrMeta` 只影响展示（比对与导出不受影响）；
`PUT` 的键校验（空/重复/自相矛盾）。

**实机验证（dev-server）**：该机有 46 条资产、4 种类型、43/46 的受限对照（见资产域的既有记录），
判据：① 模型页/接口列出的属性键与台账详情里看到的一致（逐类型抽一个）；② 把某类型的 `runtimeFields`
加一个键（例如 `cpuCores`）→ **跑一次巡检，该字段不再出现在差异里**；去掉后恢复 → 证明配置真的生效
且可回退；③ 受限账号看到的统计数小于全局；④ 属性值不出现在响应里（用真实值反向断言）。

**未覆盖边界（不得视为通过）**：浏览器实点（页面的编辑交互与提示）；自定义类型（本批不做）；
属性说明在多类型之间的**一致性**（同一个键在不同类型上填了不同中文名，不做自动校验）。

### 7.1 与设计件的偏离／修正（都是"更准或更实"的方向）

1. **D10 的值规范化不用做**：`normalizeValue`（`model.go:634-636`）**已经**忽略首尾空白与大小写差异，
   而且比设计件说的更多（还忽略大小写）。本批因此不动它，只在设计件里如实标注。
   **容忍列表**仍未做，`TypeSchema.Tolerance` 只留了位置。
2. **"疑似同义键"的规则比设计件举的例子更宽也更准**：按「小写 + 去分隔符」归一，因此
   `cpu_cores` / `cpu-cores` / `CPU.Cores` / `cpuCores` **会**成一组（这正是最常见的一类）；
   而设计件举的 `cpu` 与 `cpuCores` 不成组（归一后不同形）。语义相近但写法不同的**不猜**——
   自动合并是不可逆的数据破坏。
3. **顺带修了一处被模型放大出来的既有问题**：「缺失」这一侧原先没按当前字段范围裁剪。
   模型把某字段移出关注集合后，它会被报成"缺失"（配置项没被删，只是不再比对了）；
   显式给了 `fields` 的巡检也会把上一次快照里其它字段全报成缺失。现在两侧共用同一个 `focusPlan`，
   「缺失」回到它的本义：**当前关注的字段在资产上消失了**。这是一处**行为变更**（更准，但确实是变更）。
4. **模型变更写审计**（`Action: asset_model:update`）：与单条资产写不同——它改的是全平台的比对口径，
   而且没有变更历史可查。
5. **属性键的字符集校验仍然没有**（设计件 §1 把它列为现状之一）：存量属性键从未校验过，
   写侧定得太紧会出现"属性已经存在、却没法给它写中文名"。本批只对**模型键**做宽松校验
   （非空、无空白/控制字符、≤128）。
6. **前端"多处硬编码"里有两处是有意保留的**：新建资产表单只提供主机/中间件实例
   （Pod/工作负载由清单上报产生，手工建会被下一轮覆盖或变成孤儿）；`typeLabel` 对中间件实例仍按
   自然键前缀显示具体产品名（类型的标题是"中间件实例"，对不上 Redis/MySQL 这种产品）。
7. **界面的一处稳妥处理**：若用户没动过运行态字段（当前生效的就是内置默认那一份），保存时提交**空数组**
   （= 继续用内置默认），否则"只改了个中文名"会把默认清单固化进模型，将来内置默认调整再也影响不到它。

### 7.2 用例结果

- `asset` 包 8 组：存量行为逐字不变、配了运行态字段后不再产生差异且不报缺失、关注字段集限定比对、
  属性说明不影响比对、校验与坏 schema 回退（按内置默认且不报错）、改完不重启即生效、
  类型画像的统计与范围口径、同义键只认写法变体。
- `api` 包 4 组：**响应里不得出现属性值**（用真实值反向断言）、统计随范围收窄而模型不受限、
  保存的权限/校验/未知类型（400 与 404 分开）、未启用 503。
- 前端 6 组：类型清单与字段画像、只改中文名时提交空数组、关注字段的提交与说明、改过运行态字段时提交显式清单、
  无写权限只能查看、取不到模型时给错误。
- `go vet` / `go test ./...` **30 包全绿**；前端 `npm test` **21 文件 129 项**通过、`npm run build` 通过。

### 7.3 实机验证计划（待 dev-server 升 1.30.45）

1. **字段清单与台账一致**：模型页某类型的字段键，与该类型资产详情里看到的属性键对得上（抽两个类型）。
2. **决定性判据**：把某类型的运行态字段加一个键（例如主机加 `cpuCores`）→ 改一次该字段 →
   **跑一次巡检，该字段不再出现在差异里**；清空后恢复（回到"全部减运行态"）。
3. **统计口径**：受限账号看到的资产数与覆盖度小于全局；而**类型与字段定义两者一致**（模型不受限）。
4. **不泄露值**：响应体里不出现任何属性值（用一个真实存在的值反向断言）。
