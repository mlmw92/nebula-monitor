# 节点分组资源范围与服务可靠性修整设计

日期：2026-09-27

## 意图与边界

基于当前监控系统的现有权限与指标查询流程，消除受限用户通过不同参数形式读取范围外节点数据的路径，同时保留「指标浏览 / 自定义仪表盘按指标跨节点查看」体验。补齐测试告警权限门控、Server HTTP 超时与优雅停止、关键前端回归测试，修订与实现不符的路线图描述。此设计不新增身份系统、不变更 TSDB 的 `storage.Storage` 接口，也不扩张到其他新功能；未启用认证或拥有全局资源范围的行为保持不变。

## 现状与依据

- `permitNode` 只读取路由中的 `{name}` / `{node}` 和查询参数 `node`，而进程 / 监听端口 / 防火墙 handler 使用 `hostname`；因此授权目标和读取目标不一致。`internal/server/api/auth.go`、`internal/server/api/query.go`。
- `query/range`、指标导出允许 `node` 为空以支持跨节点视图；当前直接查询 TSDB 并把原始结果返回，未作节点范围过滤。`query/latest` 虽要求 `node`，但 `labels.node` 可与该参数冲突；导出的 `labels` 文本可覆盖 `node` 标签。`metrics/active` 未指定节点时把跨节点任何序列都视为 active。`internal/server/api/query.go`、`export.go`、`catalog.go`、`internal/server/storage/vm.go`。
- 集中日志接口已采用受限用户预先收窄可见节点集合、空集合绝不退化为全量的先例。`internal/server/api/logs_api.go`。
- `POST /api/v1/alerts/test` 会写事件并向通知渠道发消息，但路由没有权限点。Web 告警页的按钮也没有权限可见性判断。`internal/server/api/query.go`、`test.go`、`web/src/components/AlertsView.vue`。
- 当前 `http.Server` 未配置读头 / 空闲超时或优雅退出。`cmd/server/main.go`。`README.md` 与 `CONTEXT.md` 关于「仅权限管理受校验」的描述和现有路由表不一致。

## 服务端资源范围设计

1. 在 API 层建立供指标读取复用的节点参数与结果范围规则，不依赖前端隐藏。针对 `query/range`、`query/latest`、`metrics/export`：先解析有效目标节点，拒绝 `node` 与 `labels.node` 不一致或空 `labels.node` 的冲突输入（400）；明确指定可见节点按原语义访问，指定范围外节点返回 403 并记录拒绝审计；受限用户指定未知 / 不可归属节点时不得访问任何指标。未指定节点的跨节点查询仍可执行，响应只保留已注册且属于授权分组的序列；没有可见节点时不查询 TSDB，返回空结果。CSV 在裁剪后决定单序列 / 多序列格式，防止范围外序列影响导出结构。受限用户的节点标签缺失 / 归属不明序列一律剔除；全局和无认证场景维持原来的结果。
2. `metrics/active` 不以范围外序列判定为「有数据」；受限用户未指定节点时仅扫描可访问节点的存在性或先查询后过滤，若无授权节点直接返回全部 inactive。优先避免范围外 TSDB 查询；如现有 `Storage` 只支持单节点或跨节点查询，允许跨节点查询后裁剪，但不得泄漏范围外的计数、序列、单序列/多序列差异。此优化仅改变受限用户的可见结果，不改变目录本身。
3. 为以 `hostname` 作为目标的进程、监听端口、防火墙状态等路由显式指定授权参数；请求参数与 handler 实际查询目标须一致。带多个节点候选参数而值矛盾时拒绝请求，不用优先级选择绕过检查；单节点受限用户访问未知节点采用不可归属即拒绝，不泄露详情。`GET /api/v1/alerts` 的 `hostname` 参数虽有结果过滤仍一并核对。
4. 测试在真实路由表上构造 `g1`/`g2` 节点和假 TSDB：覆盖空节点跨节点、`node` + `labels.node` 冲突、导出标签覆盖、范围外显式节点、无授权节点、缺失节点标签、全局/无认证兼容、`hostname` 绕过及无权限告警测试调用。先确认测试失败，逐项修复。

## 告警与前端

- `POST /api/v1/alerts/test` 复用 `notify:write`，因为它可能发送实际通知；前端告警页测试事件按钮仅在 `useAuth().can('notify:write')` 时显示。服务端独立审计拒绝；不把它限定为 `alerts:write` 以避免「能管理规则就能触发通知」。未启用认证仍沿用现有兼容逻辑。
- 前端补代表性的交互测试：授权加载后按钮可见性、跨节点指标浏览 / 导出调用及 403 错误呈现，重点保障多用户模式体验；测试以服务端为安全边界，不把前端判定当作授权依据。若测试复杂度超出预期，保持可测试性的小范围提取，不大规模重构页面。

## Server 生命周期

- 为 `http.Server` 添加有限的 `ReadHeaderTimeout`、`IdleTimeout`，不直接设置全局 `WriteTimeout`，以免中断现有 WebSocket 长连接；涉及上传和上报的请求体仍由当前业务上限控制。
- 接收 SIGINT / SIGTERM 后以有界上下文调用 `Shutdown`，允许常规 HTTP 请求完成，随后取消后台任务上下文；对于升级流程主动重启进程 / WebSocket 长连接等特殊路径，确认不会造成停机挂住，有必要时显式关闭 Hub 连接而不是无限等待。监听异常不视为正常停止，保留清晰的错误日志和退出状态。

## 风险与取舍

受限用户跨节点查询采用「TSDB 获取序列 → 按授权节点过滤」保留现有接口和图表语义，但查询本身仍有跨节点成本。现有 7 天范围、step 下限和 TSDB 超时继续生效；后续若性能实测成为瓶颈，再增加受限节点 PromQL 选择器能力或批量 API，并在新的设计中处理后端差异。带节点归属的安全边界优先于无节点序列的显示完整性；任何无 `node` 标签的序列对受限用户默认不可见，不悄悄视为全局公共数据。Server 自监控 `self_*` 序列实际上带有 `node` 标签，是否可见仍取决于其节点是否在受限用户授权的节点分组中。
