# Nebula Monitor 系统巡检问题清单

## 文档说明

- 首次巡检日期：2026-08-08
- 巡检范围：Server、Agent、Web、大屏、升级流程、部署脚本及数据接口
- 当前状态：首批修复已完成，剩余问题继续跟踪
- 更新方式：每完成一项修复，补充修复版本、变更文件和验证结果，并将状态改为“已完成”或“部分完成”

## 优先级定义

- P0：存在明显安全风险或可能导致系统不可用

- P2：架构债务、运维风险或体验问题

## 问题清单

### SA-001：WebSocket 未经过登录鉴权

- 优先级：P0
- 状态：已完成（待集成环境验证）
- 涉及文件：`internal/server/api/auth.go`、`internal/server/api/ws.go`
- 现象：开启登录认证后，`/ws` 仍被认证中间件列为公开路径。WebSocket 握手只校验 Origin，不校验登录 Cookie 或 Bearer Token。
- 影响：未登录客户端可能订阅实时节点指标和告警数据。
- 建议：在 WebSocket 握手阶段复用登录 Token 校验；认证关闭时保持现有行为。
- 修复记录：移除 `/ws` 公开路径，认证开启时统一由 `AuthMiddleware` 校验 Cookie/Bearer Token。
- 验证结果：`go test ./...` 通过；浏览器登录态连接流程需在集成环境验证。

### SA-002：安装信息接口可能泄露 Agent 接入密钥

- 优先级：P0
- 状态：已完成（待集成环境验证）
- 涉及文件：`internal/server/api/query.go`
- 现象：`/api/v1/install-info` 返回完整的 `--secret` 参数和 `secret` 字段。当登录认证关闭、Agent 接入密钥开启时，该接口可能被匿名访问。
- 影响：泄露长期 Agent 密钥后，攻击者可伪造 Agent 上报数据。
- 建议：取消返回长期密钥，改为一次性安装令牌、短期令牌或管理员手动填写密钥；同时删除响应中的冗余 `secret` 字段。
- 修复记录：Agent 接入认证开启但 Server 登录认证关闭时，安装信息接口返回 403，拒绝泄露长期密钥。
- 验证结果：`go test ./...` 通过；需在登录开启/关闭两种部署模式验证安装引导。

### SA-003：系统升级缺少严格版本语义校验

- 优先级：P1
- 状态：已完成（待构建包验证）
- 涉及文件：`internal/server/upgrade/upgrade.go`、`internal/server/api/upgrade.go`
- 现象：上传和应用升级包时，未严格校验目标版本是否高于当前版本，也未充分使用 `previous_version_min`；同版本或低版本包存在被普通升级流程应用的可能。manifest 中的 checksum 在上传时被重新计算，但应用流程未执行独立完整性校验。
- 影响：可能误覆盖当前版本，或者绕过最低兼容版本要求导致升级后不可启动。
- 建议：使用 SemVer 解析并比较版本；普通升级禁止降级和同版本覆盖；回退只允许走回退接口；应用前重新校验 manifest 和组件 checksum。
- 修复记录：加入 SemVer、最低兼容版本、组件 checksum 和 manifest 路径校验；普通升级禁止同版本和降级。
- 验证结果：新增升级版本与路径测试，`go test ./...` 通过。

### SA-004：升级失败可能留下不完整的 Web 或混合版本

- 优先级：P1
- 状态：部分完成
- 涉及文件：`internal/server/upgrade/upgrade.go`
- 现象：Web 目录同步前会清理目标目录，复制过程中失败时可能只留下部分文件。Server、Web、Agent 任一组件失败后没有统一事务回滚。
- 影响：前后端版本不匹配、页面白屏、服务重启后无法正常运行。
- 建议：先同步到临时目录，校验完成后整体原子替换；组件替换失败时自动恢复本次备份；升级结果应明确区分“完全成功”和“部分成功”。
- 修复记录：Web 使用暂存目录切换；Server、Web、Agent 文件替换使用原子替换；组件失败时恢复已替换的 Server/Web。
- 验证结果：`go test ./...` 通过；磁盘空间不足和 systemd 重启失败仍需部署环境演练。

### SA-005：Nginx 分析存在两套数据实现

- 优先级：P1
- 状态：已完成
- 涉及文件：`web/src/components/screen/NginxAnalysisPanel.vue`、`web/src/components/screen/tabs/NetworkTab.vue`
- 现象：新的网络 Tab 已支持 Nginx 多实例筛选，旧的 `NginxAnalysisPanel.vue` 仍使用旧响应结构和全局汇总逻辑，不支持实例选择和实例地理筛选。
- 影响：旧组件一旦重新启用，会出现功能倒退、接口解析错误和不同页面展示口径不一致。
- 建议：删除废弃组件，或抽取统一的 Nginx 数据 composable/API 模型供所有入口复用。
- 修复记录：删除未被主界面引用的旧 `NginxAnalysisPanel.vue`，保留 `NetworkTab.vue` 作为唯一大屏 Nginx 分析入口。
- 验证结果：前端构建通过。

### SA-006：大屏存在重复刷新和异步请求竞态

- 优先级：P1
- 状态：部分完成
- 涉及文件：`web/src/components/screen/ScreenView.vue`、`web/src/components/screen/tabs/NetworkTab.vue`、`web/src/components/screen/composables/useScreenData.js`
- 现象：大屏父组件定时刷新基础数据，网络 Tab 又单独每 30 秒刷新 Nginx 数据；接口响应较慢时，多个刷新周期可能重叠，旧请求可能晚于新请求返回并覆盖结果。
- 影响：请求量增加、服务端压力增大、页面偶发显示旧数据或不同步数据。
- 建议：统一由页面级刷新调度器管理请求；增加请求序列号或 AbortController，组件切换和卸载时取消未完成请求。
- 修复记录：移除父级 `useScreenData` 对 Nginx 汇总的重复请求；Network Tab 增加刷新互斥，避免刷新周期重叠。
- 验证结果：前端构建通过；AbortController 和延迟响应覆盖测试仍待补充。

### SA-007：通用趋势查询缺少时间范围和步长限制

- 优先级：P1
- 状态：已完成（待压测验证）
- 涉及文件：`internal/server/api/query.go`
- 现象：`/api/v1/query/range` 未严格校验 `start/end`，也没有最大查询跨度限制；异常或恶意参数可能形成超大范围查询。指标导出接口已有跨度限制，但普通查询没有。
- 影响：可能拖慢 VictoriaMetrics 或其他时序库，造成 Server 响应变慢甚至资源耗尽。
- 建议：校验时间戳和 `end > start`；限制最大跨度、最小 step、最大返回序列数；对非法参数返回 400。
- 修复记录：增加时间戳、跨度、step 合法性校验，普通趋势查询最大跨度限制为 7 天。
- 验证结果：`go test ./...` 通过；需在真实 TSDB 上验证大查询压力效果。

### SA-008：实例注册表和 Nginx 地理窗口仅保存在内存

- 优先级：P2
- 状态：待处理
- 涉及文件：`internal/server/instancereg/registry.go`、`internal/server/nginxaccess/window.go`、`cmd/server/main.go`
- 现象：Server 重启后，中间件实例注册表和 Nginx 访问地理聚合窗口都会丢失。实例注册表主要依赖最近上报，没有统一的持久化和过期策略。
- 影响：重启后实例暂时消失；长期离线实例可能继续显示为已配置但状态不明确；Nginx 地理统计无法追溯。
- 建议：实例配置持久化并记录最后上报时间；增加离线/过期状态；Nginx 实时窗口明确标注统计范围，必要时将聚合结果持久化到时序库。
- 验证标准：Server 重启后实例仍可展示；长期未上报实例按规则变为过期；大屏明确区分实时窗口和历史数据。

### SA-009：部分 HTTPS 采集默认允许跳过证书校验

- 优先级：P2
- 状态：已完成（待自签证书场景验证）
- 涉及文件：`internal/agent/collector/nginx.go`、`internal/server/dialtest/dialer.go`
- 现象：Nginx 采集器和 HTTPS 拨测代码存在 `InsecureSkipVerify: true`。
- 影响：在跨主机或不可信网络中可能遭受中间人攻击，采集结果也可能被伪造。
- 建议：默认校验证书；允许用户显式配置跳过校验时给出安全警告，并区分 CA 文件、主机名和跳过校验三种模式。
- 修复记录：Nginx 配置增加 `insecureTLS`，默认执行证书校验；拨测 HTTPS 默认使用系统 CA 校验。
- 验证结果：Agent Collector 测试和 `go test ./...` 通过。

### SA-010：TSDB Docker 部署默认暴露管理端口且使用 latest 镜像

- 优先级：P2
- 状态：部分完成
- 涉及文件：`deploy/install-tsdb.sh`、`deploy/docker/docker-compose.yml`
- 现象：Thanos、VictoriaMetrics 等容器端口直接映射到宿主机，部分接口缺少认证；部署脚本使用 `latest` 镜像标签。
- 影响：时序库管理接口可能被外部访问；镜像自动变化可能造成不可预期升级或兼容性问题。
- 建议：默认绑定 `127.0.0.1`，只暴露 Server 必需端口；支持固定版本镜像并记录实际镜像版本。
- 修复记录：Docker Compose 和 TSDB 安装脚本的 TSDB/Thanos 端口默认绑定 `127.0.0.1`。
- 待处理：安装脚本中的 `latest` 镜像标签仍需改为可配置且可复现的固定版本。
