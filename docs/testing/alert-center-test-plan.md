# 告警中心专项测试文档

- 测试对象：告警规则、评估引擎、告警事件存储、静默/维护/抑制/分组、通知、拨测联动、告警中心 Web 页面
- 文档状态：整改基线
- 优先级：P0=会导致告警引擎停止、漏报或数据错误；P1=核心告警行为错误或可能重复/误发；P2=统计、体验、运维和安全完善项

## 1. 测试范围

### 1.1 规则与评估

| ID | 优先级 | 场景 | 预期 |
|---|---|---|---|
| ALERT-R01 | P0 | 阈值规则六种运算符、`for=0`、正持续时间 | 只在条件满足并达到持续时间后 firing |
| ALERT-R02 | P0 | firing → resolved，检查 startsAt/endsAt 和历史排序 | 恢复时间正确，事件可查询且状态正确 |
| ALERT-R03 | P0 | 规则配置周期静默：合法时间、非法时间、跨天时间 | 不 panic；命中静默时不触发；跨天判断正确 |
| ALERT-R04 | P1 | `alert.enabled=false`、规则停用、规则删除 | 引擎不再评估；已有 firing 状态被清理或明确标记 stale |
| ALERT-R05 | P1 | 节点离线、服务离线、主从切换、集群无主/多主 | 触发、去重、恢复和消息内容正确 |
| ALERT-R06 | P1 | Server 重启后仍有 firing 告警 | 不重复告警；已有状态、抑制关系和升级计时可恢复 |

### 1.2 事件存储与告警中心

| ID | 优先级 | 场景 | 预期 |
|---|---|---|---|
| ALERT-S01 | P0 | firing/resolve 事件写入时序库 | 两种状态均使用真实事件时间 |
| ALERT-S02 | P1 | firing 持续超过 7 天、TSDB 默认 lookback | 仍显示为活跃告警，不因查询窗口消失 |
| ALERT-S03 | P1 | 抑制源先触发、目标先触发、源恢复 | 目标始终按当前抑制状态发送/补发通知 |
| ALERT-S04 | P1 | 同一规则同一节点多轮恢复后再次触发 | 新一轮告警默认未确认 |
| ALERT-S05 | P2 | 统计接口“24h 事件” | 只统计最近 24 小时，不混入历史事件 |

### 1.3 静默、维护、升级与分组

| ID | 优先级 | 场景 | 预期 |
|---|---|---|---|
| ALERT-A01 | P1 | 单次静默、周期静默、全局维护窗口叠加 | 事件留痕；通知抑制范围符合产品定义 |
| ALERT-A02 | P1 | 分组开启，规则分别配置不同通知渠道 | 每个渠道只收到允许的告警组 |
| ALERT-A03 | P1 | 分组等待/间隔、热更新配置 | 不丢失未发送事件，不重复发送 |
| ALERT-A04 | P1 | 升级级别、升级渠道、重复提醒 | 按升级配置发送，不能绕过维护和渠道限制 |

### 1.4 通知与拨测

| ID | 优先级 | 场景 | 预期 |
|---|---|---|---|
| ALERT-N01 | P1 | Webhook 返回 2xx、4xx、5xx、超时 | 非 2xx/超时明确失败并可观测 |
| ALERT-N02 | P1 | 空通知渠道、指定通知渠道 | 空值语义与前端显示一致；指定渠道不误发 |
| ALERT-N03 | P2 | 手动测试告警 | 不制造永久活跃告警，不污染统计 |
| ALERT-N04 | P1 | 拨测故障、恢复、证书 30/7/0 天 | 状态去重、恢复和级别升级正确 |

### 1.5 权限与前端

| ID | 优先级 | 场景 | 预期 |
|---|---|---|---|
| ALERT-W01 | P1 | 告警确认、批量确认、不同用户确认 | 操作人来自认证身份；新一轮告警不继承旧确认 |
| ALERT-W02 | P2 | 通知测试失败、规则导入失败 | 页面显示真实错误，不出现二次 JavaScript 异常 |
| ALERT-W03 | P1 | 规则非法 operator/for/service/notify | 服务端返回 400，不写入无效规则 |
| ALERT-W04 | P2 | 告警名称、节点名、消息包含 HTML 特殊字符 | 页面和邮件均安全转义 |

## 2. 整改优先级

### P0

- 修复周期静默时间解析越界和下标错误。
- 修复恢复事件使用 `StartsAt=0` 写入的问题。
- 让 `alert.enabled` 配置生效。
- 修复告警事件查询的 lookback/长期活跃问题。

### P1

- 修复抑制状态计算和持久化顺序。
- 处理规则停用、删除、节点消失后的 firing 状态。
- 重新设计确认状态，使其绑定具体告警轮次。
- 分组通知按规则渠道拆分。
- Webhook 检查非 2xx 响应。
- 增加规则服务端校验和告警状态重启恢复。

### P2

- 修复 24 小时统计口径。
- 测试告警自动恢复或排除出活跃统计。
- 修复前端 `ElMessageBox` 导入。
- 异步化通知发送，避免阻塞评估锁。
- 增加邮件 HTML 全字段转义和告警审计信息。

## 3. 验证门槛

- P0 用例全部自动化通过。
- P1 用例至少覆盖服务端单元测试和一个端到端链路。
- `go test ./...`、`go vet ./...` 通过。
- 前端构建通过，通知失败分支无未捕获异常。
- 真实 VictoriaMetrics、Webhook 和浏览器环境完成 ALERT-S02、ALERT-N01、ALERT-W02。
